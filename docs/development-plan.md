**Validation:**
- `npx tsc --noEmit` → exit 0.
- `npx eslint .` → exit 0 (1 non-blocking warning: `import/no-anonymous-default-export` on the eslint config itself).
- `npx next build` → exit 0.

**Deviations from the spec:**
1. `package.json` `lint` script uses `eslint .` rather than `next lint`; `next lint` was removed in Next 16 and now shells out to eslint directly. Documented in the script.
2. `next.config.ts` does not include an `eslint: { ignoreDuringBuilds: false }` key — the `NextConfig` type in 16.3.7 no longer accepts it (Next 16 delegates lint to the eslint binary). Behaviour is unchanged — CI still runs `npm run lint`.
3. Node 22 pinned in CI (Node 24 is not yet on GitHub Actions runners) — matches the spec.
4. `favicon.ico` is a PNG-encoded file written with a `.ico` extension. Modern browsers accept it; a proper multi-size `.ico` can land in Phase B if needed.
5. `scripts/audit-links.mjs` ships as a health-check stub — the full crawler is queued for Phase F where the running preview URL exists.
6. `data/routes.ts` marks every route other than `/` as `pendingContent: true`; only `/` currently appears in `sitemap.xml` output. Routes flip in as content lands per Phase C / D / E.

## Phase A — Foundation

- **Objective:** empty repository → runnable Next.js scaffold with tokens + CI green.
- **Tasks:**
  1. Confirm GitHub repo state; establish `main` branch protection.
  2. `npx create-next-app@latest` (App Router, TS, Tailwind v4, ESLint) — configured to match [`architecture.md`](architecture.md).
  3. Add `trailingSlash: true`, image formats, security headers to `next.config.ts`.
  4. Add `tsconfig.json` with `strict: true`.
  5. Add `AGENTS.md`, `docs/` (this planning folder), `README.md`.
  6. Add `.env.example`.
  7. GitHub Actions: `lint`, `typecheck`, `build` on every PR.
  8. Vercel project connect + preview deploys enabled.
  9. Add `not-found.tsx`, `robots.ts`, `sitemap.ts` skeletons (with empty route data).
- **Dependencies:** repo access, Vercel account, DNS control (for later phases).
- **Deliverables:** repo with green CI, live preview URL.
- **Risks:** SSH auth to GitHub, Vercel org access.
- **Acceptance:** CI green on `main`; `preview.vercel.app` URL renders a minimal homepage stub.

## Cross-phase governance

- **No `--no-verify`, no `ignoreBuildErrors: true`.**
- **No page ships with unresolved `[VERIFICATION REQUIRED: …]` blocks in production.**
- **Every PR** updates whichever `docs/` file its change affects. Docs are part of the diff, not a separate task.
- **Every URL change** logs a 301 in `next.config.ts` + `docs/seo/redirects.md` in the same PR.

## Risk register (top 5)

| Risk | Impact | Mitigation |
|---|---|---|
| Client cannot provide verified certifications | Blocks `/quality/` copy | Ship the page without those claims; publish only what's true. |
| Delayed photography | Blocks product / facility pages | Use provisional generic product silhouettes with a `[PHOTO TO REPLACE]` note; hide route from sitemap until real photos land. |
| DNS / registrar access gap | Blocks launch | Confirm registrar access before Phase A. |
| Resend not delivering to client's inbox | Blocks RFQ conversion | Configure SPF/DKIM in Phase C; test end-to-end before Phase D. |
| Late scope creep ("we want a blog / dark mode / 20 city pages") | Delays launch and risks Helpful-Content penalties | Point at AGENTS.md §38 + this doc; require written change order. |
